用 Hexo + GitHub Pages 搭建免费个人博客（完整步骤）

本文记录这套博客从零到上线的完整流程，适合完全没接触过 Hexo 的人照做。

一、整体架构

写作只发生在本机：Markdown 文章由 Hexo 在本地渲染成静态 HTML，再把生成好的 public/ 目录推送到 GitHub 仓库的一个分支，GitHub Pages 负责对外提供访问。

Markdown 源文件  → Hexo 生成   静态 HTML  → git push   GitHub Pages\text{Markdown 源文件} \;\xrightarrow{\ \text{Hexo 生成}\ }\; \text{静态 HTML} \;\xrightarrow{\ \text{git push}\ }\; \text{GitHub Pages} Markdown 源文件 Hexo 生成 ​静态 HTML git push ​GitHub Pages

好处是：服务器、数据库、域名全部不需要，访问速度快且永久免费。

三、创建 GitHub 仓库

登录 GitHub，点击右上角 + → New repository，然后二选一：

  1. 项目站（推荐新手）：仓库名随便取，例如 myblog，公开（Public）。
    访问地址形如 https://<用户名>.github.io/myblog/。
  2. 用户站：仓库名必须是 <用户名>.github.io。
    访问地址形如 https://<用户名>.github.io/，此时站点根路径 root 要改成 /。

注意：免费账号的 Pages 对公开仓库开放；仓库设为私有后 Pages 需要付费方案。

创建后先不要勾选任何初始化文件（README 之后会自动生成）。

八、开启 GitHub Pages

推送成功后：

  1. 打开仓库 → Settings → 左侧 Pages
  2. Source 选择 Deploy from a branch
  3. Branch 选 gh-pages，目录选 / (root)，点击 Save
  4. 等待约 1 分钟，页面顶部会显示站点地址

之后每次 publish，GitHub Pages 都会自动重新发布，一般几十秒后生效。

九、绑定自定义域名（可选）

如果你有自己的域名：

  1. 在 source/ 下新建文件 CNAME，内容只有一行域名，例如 blog.example.com
  2. 在域名服务商添加 CNAME 记录，指向 <用户名>.github.io
  3. 在仓库 Settings → Pages 中勾选 Enforce HTTPS

十、常见问题

Q1：刷新 404 / 页面样式错乱？
八成是 url 与 root 没和仓库名对齐，改完务必 npx hexo clean 再重新生成。

Q2：推送失败 Authentication failed？
GitHub 已禁用密码认证，请到 Settings → Developer settings → Personal access tokens 生成 token，勾选 repo 权限后作为密码输入。

Q3：公式不显示？
本工程已用 markdown-it + KaTeX 在构建期渲染，无需前端 JS。注意行内公式写成 $x$ 且美元符号紧贴内容，块级公式的 $$ 必须独占一行、前后留空行。

Q4：文章图片怎么放？
post_asset_folder: true 已开启，hexo new "标题" 会同时生成同名文件夹，把图片放进去，正文写 ![](图片名.png) 即可。
